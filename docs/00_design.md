## 1. 算法实例化（与代码逐条对应）

环 `R = Z_q[x]/(x^n − 1)`，`q = 2048 = 2^11`，`p = 3`。
参数集取自 `tbuktu/ntru` 的 `EncryptionParameters`（论文引的 IEEE P1363.1 [28]）：
EES1087EP2 / EES1171EP1 / EES1499EP1，外加 **APR2011_439**（代码里沿用旧名 `EES439`；
EES 族**没有** 439 —— 这一组的字段曾被错读，已于 2026-10-14 修正，见 `工程复盘.md` §6.1(b)）。
ntru 的 `dg`、`dr` 不是独立参数，由 `init()` 推导：**`dr = df`，`dg = N/3`**。

| 步骤 | 公式 | 代码 |
|---|---|---|
| 私钥 | `F` 三元（df 个 +1、df 个 −1）；`f = 1 + p·F`（**注意 "1" 是常数项**） | `keygen` in `ntru.cpp` |
| 公钥 | `g` 三元（dg/dg）；`h = p·g·f^{−1} mod q` | 同上 |
| 加密 | `C = h·s + M`，`s` 三元（dr/dr），`M ∈ R/p` | `encrypt` |
| 解密 | `a = f·C mod q` → 取中心代表 → `M = a mod p`（输出 {−1,0,1}） | `decrypt_with_noise` |
| 委托 | `rk_{A→B} = f_A · f_B^{−1} mod q` | `rekeygen` in `pre_base.cpp` |
| 重加密 | `C_B = C_A · rk + p·e`（`e` 小多项式，重量 `dr`） | `reencrypt` |

**正确性**：
- 原始：`f·C = p·g·s + f·M = p(g·s + F·M) + M`（用了 `f = 1 + pF`）→ mod p 得 `M` ✓
- 重加密：`f_B·C_B = f_B·C_A·f_A·f_B^{−1} + p·e·f_B = f_A·C_A + p·e·f_B` → mod p 得 `M` ✓
- 噪声：`‖center(f·C)‖_∞` 实测（EES439，`smoke` 固定种子）约 184（原始）、499（重加密），远小于 `q/2 = 1024` ✓

**两个实现要点（都已在代码里注释）**：
1. `f ≡ 1 (mod p)` 不是优化，是**正确性的必要条件**（`f` 出现在明文那一项上）。
   —— 值得一提的是：ntru 库本身**只有 product-form 变体**才这么做，普通参数集用 `f = t`；
   论文作者在 `privatePolynomial()` 里**无条件覆盖成 `1 + 3t`**，所以本项目的实现与论文一致。
2. `p·e` 也不是可选项：没有它，接收者用 `f_B·C_B = f_A·C_A` 就能直接解出 `f_A`（只要 `C_A` 在 `R_q` 中可逆）。

**已知安全缺陷（必须写进报告，不许回避）**：
- `rk · f_B = f_A`：**代理 + 任一接收者合谋 → 直接得到委托方私钥**（零成本，不需要格约化）；
- `rk` 是"小多项式 / 小多项式"的形状，可被多密钥 NTRU 格攻击恢复私钥（Liu–Pan–Zhang, [ePrint 2019/083](https://eprint.iacr.org/2019/083) 及 2024 年多项式时间版本）；
- 抗合谋 NTRU PRE 已有前人工作（JISA 2023）→ **本项目不主张"抗合谋"，主张的是"提高腐化阈值"**。

| 原待验证命题 | 结论 |
|---|---|
| partial 被别的代理看到会泄漏什么 | 只泄漏 `share mod p`；而 `Σ share = rk` 且 `f_A ≡ 1 (mod p)` ⇒ 泄漏的只是接收者自己公钥的信息。完整推导见 `最终报告.md` §2.5 |
| 组合者是否获得关于 `rk` 的额外信息 | 否 —— 单个组合者的视野等价于基线的单代理，门限化降低的是"单个代理持有完整凭证"的信任要求，**不降低对聚合方的信任要求**。见 `最终报告.md` §2.6 |
| `e_S` 的重量是否要按门限层数放大 | 不需要。组合后的噪声是 `m = C(N,t−1)` 份独立同分布噪声之和，实测增长慢于 `m`（`√m` 量级）。见 `最终报告.md` §2.7.3 |

## 3. 不能声称的东西（答辩红线）

1. 不能说 NTRUReEncrypt "安全"——它已被攻破；我们只主张**腐化阈值从 1 个代理提高到 t 个代理**（且这条在信息论层面可证）。
2. 不能说"抗合谋"（前人已做，且我们的构造里 `t` 个代理合谋仍可恢复 `rk`）。
3. 不能说"首次用 GPU 做格上 PRE"（Dai–Doröz–Sunar 做过 NTRU GPU；Sahu–Rohloff CANS 2020 做过格上 PRE GPU）。
4. 演示用的 `n=7` / `n=61` 沙盒参数**安全性为零**，只能用于功能验证；任何性能/安全结论都要标注参数集与安全级别。
5. C2 输出的是**噪声预算**，不主张任何新的安全性；不能由 `h_max(δ)` 推导出"方案安全"。
