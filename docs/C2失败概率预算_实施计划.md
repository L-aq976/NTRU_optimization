## 1. 为什么做、做成什么样

论文只给出"经验最大跳数"（如 EES1171 → 21 跳），但**没有说这个跳数对应的解密失败概率是多少**。C2 把它升级成一个**预算**：

> 给定目标失败概率 δ（低到 `2^-40`），反解出可支持的跳数 `h_max(δ, 参数, 门限配置)`。

并给出"门限化提高腐化阈值 → 噪声放大 → 可用跳数下降"的代价曲线 —— 这条曲线是 C1 与 C2 的结合点，也是报告的核心图之一。

## 3. 噪声模型（C2 的数学基础）

h 跳链 `A → B1 → … → Bh`，用 `f_Bh` 解密：

```
f_Bh · C_Bh = f_A·C_A + p·Σ_{i=1..h} e_i·f_Bi
            = p·( g·s + F_A·M + Σ_{i=1..h} e_i·f_Bi ) + M
```

定义**噪声核** `T_h = g·s + F_A·M + Σ_{i=1..h} e_i·f_Bi`。

**判据与 C++ `decrypt_with_noise` 逐位一致**：`center(p·T_h + M) mod q`，再 `mod p`，必须等于 `M`。

### 3.1 为什么这个模型适合做大偏差分析

`Σ(g) = Σ(F_A) = Σ(e) = 0`，`Σ(f_B) = 1` ⇒ `Σ(T_h)` 是常数 ⇒ **系数零均值，方差随 h 线性增长**。这正是大偏差/鞍点分析的标准结构（i.i.d. 增量之和）。

### 3.2 只在小整数域做卷积

操作数是 `e ∈ {−1,0,1}` 与 `f_B = 1 + 3F_B`（系数 `∈ {−2,1,4}`），**从不碰满量程的 `C_A·rk`**。这条设计选择后面直接决定了 FFT 后端可以做到无损取整（见 §4.2）。

### 3.3 C1 耦合：一个极简的改写 ★

门限组合是对全部 `m = C(proxy_N, t−1)` 份 partial 求和，每份各带一个 `p·e_S`，且**共用同一个** `f_B`：

```
Σ_S (C_A·share_S + p·e_S) = C_A·rk + p·Σ_{k=1..m} e_k
```

即：**门限版完全等价于基线把 `e_i` 换成 `Σ_{k=1..m} e_k`**。

实现上的好处：先把 m 份三元多项式求和成一个 `E`，再每跳只做**一次**卷积 —— 代价 O(m) 次采样。m 到几百也很便宜。

### 4.1 新建 `pyref/hop_sim.py`（数值核心，约 350–450 行）

按 `pyref/gpu_kernel.py` 的形态组织（自带 `--backend` 分派 + `--selftest`）。

**数据模型**

- `RingParams` dataclass：`name, ring_n, q, p, df, dg, dr, dm0, dm1, paper_hops`；`EES` 字典按 §2.3 的表填全（EES 四组 + 可选 TINY7/TINY61 用于验证）。

**采样**（复现 `src/core/sampler.cpp` 的固定重量语义）

- `sample_ternary(rng, B, n, d)`：`B×n`，恰好 `d` 个 +1、`d` 个 −1，其余 0；
- `sample_message_batch(rng, P, B)`：明文，`dm0` 个 +1、`dm1` 个 −1；
- `sample_sum_ternary(rng, B, n, d, m)`：C1 的 m 份求和（§3.3）。

**卷积后端三选一** —— 同一批输入必须给出**逐位相同**的整数结果：

| 后端 | 说明 | 用途 |
|---|---|---|
| `exact` | int64 线性卷积 + 折回（照搬 `ring_np.poly_mul_cyclic_fast:41-57` 的批量版） | 验证用 oracle、小批量 |
| `fft` | `np.fft.rfft/irfft` + `np.rint` | **CPU 默认** |
| `cupy` | 复用 `gpu_kernel.py:33-39` 的 `HAS_CUPY` 分派与 RawKernel 写法 | WSL，可选 |

`--backend auto` = `cupy if HAS_CUPY else fft`。

> **FFT 精确性论证**（写进 docstring）：操作数上界 `dr·4 ≤ 504`；FFT 舍入误差
> `≲ ε·O(n log n)·‖a‖∞·‖b‖∞ ≈ 1e-11 ≪ 0.5`，约 **8 个数量级余量** ⇒ 取整无损。
> 即便如此，仍以 `fft == exact` 的逐位硬测兜底（§6 断言 3）。

**判据与统计**

- `chain_failure_mask(T, M, P)`：严格按 `decrypt_with_noise` / `poly_mod_p_centered`（`src/core/ring.cpp:197`）实现；同时输出 ∞-范数代理判据 `‖p·T+M‖∞ > q/2` 供"两种口径"对照。
- `wilson_ci(k, N, z=1.96)`：**一律报区间，不报裸点估计**。

**批量 MC 主循环**

```
T = g·s + F_A·M                       # 每批采一次（h 无关的公共部分）
for i in 1..h:
    E_i = sample_sum_ternary(dr, m)   # C1 噪声；基线 m=1
    T  += cyc(E_i, 1 + p·F_Bi)        # 小 × 小
```

内存 `≈ 32·B·ring_n` 字节（同时持有 T / E / f_B / 公共部分）。默认
`B = clamp(mem_budget / (32·ring_n), 256, 65536)`，`--batch` 可覆盖。
（WSL 内存约 7.6 GB，见 `README §6`。）

**CGF 与鞍点**（全程在 **log 空间**，要能到 `2^-40 ≈ 9e-13` 不下溢）

- `estimate_cgf(P, m, n_samples, tgrid)`：用便宜的**独立单跳样本**估经验 CGF `K(t) = log E[e^{tW}]`；
- `saddlepoint_delta(P, h, tau, cgf, calib)`：

  ```
  K'(ŝ) = τ/h
  p₁(h) ≈ exp( h·K(ŝ) − ŝ·τ ) / ( ŝ·√(2π·h·K''(ŝ)) )
  双侧：p₁(τ) + p₁(−τ)
  δ ≈ ring_n · p₁        # 对 ring_n 个系数的并集界
  ```

**重要性采样（可选加分项）**

- `importance_sampling_delta(...)`：指数倾斜 IS，返回 `(δ, ESS, CI)`。**只在 ESS ≳ 100 时可信**，必须把 ESS 一起报出来。

**标定与反解**

- `calibrate(pred, measured) -> (a, residuals)`：在重叠区间（如 δ ∈ [1e-2, 1e-4]）对 `log δ` 最小二乘拟一个乘性常数 `a`；**报跨 ≥3 个数量级的最大残差（以 decade 计）**。若残差有**系统性漂移**，说明模型形状不对，必须当 blocker 处理，而不是硬拟一个常数。
- `invert_hop_budget(pred_delta, target)`：二分/Brent 反解 `h_max(δ, params, m)`。

### 硬断言（不通过即失败）

1. **采样器一致性**：恰好 `d` 个 +1、`d` 个 −1；`Σg = ΣF_A = Σe = 0`、`Σf_B = 1`。
2. **`exact` 后端 vs C++ 真值**：用**已存在**的 `bin/vectors_EES439_7.txt`（含 `FA/FB/GA/S/M/E/RK/CB`），经 `ring_np.parse_vectors` 读入后核对
   `p·T₁ + M == FB·CB`（整系数，`T₁ = (FB·CB − M)/p` 应可整除），
   且 `‖center(FB·CB)‖∞` 等于 `cross_check.py:144` 打印的那个值。
   → 可再用 `TINY61` 复一遍：`ntru_cli vectors TINY61 <seed>`（**需先重新构建** —— 现成 exe 是 `params.cpp` 改动之前的，`bin/` 被 gitignore，见 `README §6` 的构建命令）。
3. **`fft` vs `exact`**：6 个参数集（4 EES + TINY7 + TINY61）× 多个种子 × `B = 512`，在随机小操作数与真实 `e·f_B` 抽样上必须 `array_equal`（逐位相同）。
4. **判据一致**：`chain_failure_mask` 与 `poly_mod_p_centered` 的直译版在跨阈值的合成 `T` 上事件数一致，且与 ∞-范数代理判据一致。
5. **三条路径互证**：在重叠区（δ ∈ [1e-3, 1e-5]）plain MC / IS / 鞍点必须在各自 CI 内一致。

### 合理性检查（只打印，不失败）

6. **h = 1 对 C++ smoke**：`smoke EES439 3 2` 噪声 417（基线）/ 640（门限）≪ 1024 ⇒ h=1 失败率应 ≈ 0。
   这是**一致性**检查，**不是数值相等**；注意它是环 n=439，而非 TINY61（§2.2）。
7. **TINY 环零失败**：TINY7 / TINY61 上任何 h 的 δ 都应为 0（噪声 ≪ q/2）。这不是废话 —— 它是"判据在噪声远小于阈值时不误报"的负向对照。

   **只能当 sanity 目标**（原始数据源缺失），报出模拟器的 `δ(21)` 与 `h(δ=0.1)` 并标出偏差，**不做断言**。

## 7. 默认决策与风险

### 7.1 默认决策（实施时按此执行）

| 项 | 取值 | 说明 |

| `exact` 后端用途 | 仅验证与小批量 | 朴素 O(n²) 太慢，不做主力 |
| δ(h) 曲线的环 | **只用 EES 四组** | TINY7/TINY61 噪声 ≪ q/2，永不失败（§2.3） |

### 7.2 风险

1. **论文 Table 4 锚点在本机无法复现** —— 原始 `A1-4_选题方案/` 不在本机，只能作 sanity 目标。
2. **并集界 `δ ≈ ring_n·p₁` 假设各系数失败近似独立**。标定常数 `a` 能吸收均值偏差，但若残差跨 decade **系统性漂移**，说明模型形状错，当 blocker。
3. **FFT 精确性只在"小整数域"这一设计选择下成立**。若以后改成卷积满量程密文，必须重做误差界，并补最大 n / 最大 batch 的硬测。
4. **IS 在极端尾部 ESS 会崩**。必须报 ESS，只在 ESS 足够大时采信；超出区间时明确声明"只有鞍点结果可用"。
5. **代理数上限 20**。联合表不得越界，否则 C2 给出的配置 C1 实现不出来。
6. **协作面**：`docs/02_` 编号已被 `02_格在哪里.md` 占用，本文件按约定不参与编号；`src/core/params.*` 近期在动（新增 TINY 参数），若再改到 EES 四组的数值，§2.3 的表与所有已跑出的数字都要重跑。

## 8. 不写进结论的东西（沿用 `docs/00_design.md` §5 的红线）

C2 输出的是**噪声预算**，不主张任何新的安全性。具体地：

- 不能由 `h_max(δ)` 推导出"方案安全"；
- 不能声称门限化是"抗合谋"（t 个代理合谋仍可重构 `rk`）；
- 演示用的 TINY7 / TINY61 **安全性为零**（`src/core/params.h` 原文），其数字只能用于功能与算术验证，不能进任何性能/安全结论；
- 参数安全位数属另一条工作流（`docs/02_格在哪里.md` §5），C2 的噪声预算不能替代它。

任何 C2 的数字都必须标注 参数集 + 环维数 + 后端 + 样本量 + 置信区间。
