## 0. 记号与约定

| 记号 | 含义 |
|---|---|
| `R` | `Z_q[x]/(x^n − 1)`，即系数模 `q = 2048`、按 `x^n = 1` 折叠的循环卷积环 |
| 中心代表 | 每个系数落在 `(−1024, 1024]`。**本文档所有多项式都按中心代表打印** |
| `p = 3` | 明文模数。明文系数是 `{0,1,2}`，解密后得到中心形式 `{0,1,−1}` |
| `f, g, h` | 私钥、辅助多项式、公钥 |
| `M, C` | 明文、密文 |
| `rk` | 重加密密钥（委托凭证） |
| `Σ` | 多项式逐系数相加，再 mod 2048 |

> **一条最关键的约定**：`f = 1 + p·F` 里的 "1" 是**常数多项式**（只有第 0 个系数是 1，其余是 0），不是"每个系数都加 1"。整份代码里凡是出现"1""2"的地方都要这样读（这也是骨架开发时踩过的坑，见 §5）。

### 0.1 记号速查：`f_A · f_B^{-1}` 到底在说什么

| 记号 | 是什么 | **不是**什么 |
|---|---|---|
| `R` | 环 `Z_q[x]/(x^n − 1)`；元素就是"n 个系数"的向量，按 `x^n = 1` 折叠 | 不是整数，也不是矩阵 |
| `f_A` | 对象 A（Alice）的**私钥多项式** = `1 + p·F_A`，系数很小（1, ±3） | 不是大整数；它是长度为 n 的系数向量 |
| `f_B` | 对象 B（Bob）的私钥多项式，同构 | 同上 |
| `f_A^{-1}` | `f_A` 在**环里**的乘法逆元，满足 `f_A · f_A^{-1} = 1`（右边这个"1"是常数多项式） | ⚠️ **不是"逐系数取倒数"**！是模 `(x^n−1, q)` 下的环逆元，靠扩展欧几里得 + Hensel 提升算出（`poly_inv.cpp`） |
| `·` | **环乘法** = 循环卷积：`(a·b)[k] = Σ_i a[i]·b[(k−i) mod n]`，最后 mod q | ⚠️ **不是逐系数相乘**，也不是普通多项式乘法（普通乘法不折叠 `x^n`） |
| `h_A` | 公钥 = `p·g_A·f_A^{-1} mod q` | 不是 `f_A` 本身（`f_A` 被逆元打散了） |
| `rk_{A→B}` | 委托凭证（重加密密钥）= `f_A · f_B^{-1} mod q` | 不是"被加密的私钥"，就是一个普通环元素 |
| `p·e` | 掩码项：`p` 乘一个小噪声多项式 `e` | 不是可选项，去掉会让接收者反推出 `f_A` |

**`f_A · f_B^{-1}` 的一句话读法**：
> **"A 的私钥" ÷ "B 的私钥"** —— 环里没有除法，所以写成"乘 B 私钥的逆元"。
> 它是一张**换算凭证**：把"只有 `f_A` 能解开的密文"换算成"`f_B` 就能解开的密文"。

**它为什么必须长这样**（三行推导，整个方案的骨架）：

```
接收者解密要算：     f_B · C'                        ← C' 是代理转换后的密文
代理的转换是：       C' = C · rk + p·e
代入 rk = f_A · f_B^{-1}：
  f_B · C' = f_B · C · f_A · f_B^{-1} + p·e·f_B
           = f_A · C  +  p·(e·f_B)                 ← f_B^{-1} 与 f_B 精确抵消
           = [p·(…) + M] + p·(…)                    ← 正是 Alice 自己解密时算的东西
```

`f_B^{-1}` 被 `f_B` 精确消掉、只留下 `f_A`，于是 Bob 解出来的和 Alice 自己解出来的**完全一致** —— 这就是"委托"的全部数学内容。

**⚠️ 特别注意：本方案里不会出现 `f_A · f_B`（两个私钥相乘）。**
骨架与论文里出现的只有下面这几种组合，别混：

| 出现位置 | 表达式 | 含义 |
|---|---|---|
| KeyGen 自检 | `f_A · f_A^{-1} = 1` | 逆元是否正确 |
| KeyGen | `h_A = p·g_A·f_A^{-1}` | 公钥（把 `f_A` 藏起来） |
| ReKeyGen | `rk_{A→B} = f_A · f_B^{-1}` | 委托凭证 |
| Dec（A 自己） | `f_A · C` | 解密 |
| Dec（B 收到转换后密文） | `f_B · C'` | 解密 |
| **攻击** | `rk · f_B = f_A` | 代理 + 接收者合谋直接恢复 A 的私钥（步骤 8(b) 实测） |

## 1. 全景流程图

```

                    │  KeyGen:  F ← 三元;  f = 1 + p·F;  h = p·g·f^{-1}   │  src/core/ntru.cpp
                    │  Enc:     C = h·s + M            （s 小多项式）      │
                    │  Dec:     a = f·C → 中心代表 → M = a mod p          │
                    └───────────────┬────────────────────────────────────┘
                                    │  ① Alice 生成委托凭证
                                    │     rk_{A→B} = f_A · f_B^{-1}      src/core/pre_base.cpp
                                    ▼
   ┌────────── 代理 / 云服务（只有 rk，没有 f_A、f_B）──────────────────┐
   │  基线：  C' = C·rk + p·e                                          │
   │  门限：  rk 被拆成 C(n,t-1) 份子集份额（见步骤 6）                       │  src/core/threshold.cpp

        ┌──── 对象 B（接收方 Bob）────┐

        └────────────────────────────┘
```

## 2. 逐步输出与讲解

### 【步骤 1】生成密钥对 —— `src/core/ntru.cpp : keygen()`

```
  对象 A（委托方 Alice）：
    采样三元 F_A（2 个 +1、2 个 -1），并令 f_A = 1 + p*F_A
      f_A（中心形式）      = [1, -3, 0, 3, -3, 3, 0]
      f_A^{-1} mod q       = [-132, -98, 679, 539, 307, -1014, -280]
    校验 f_A * f_A^{-1}  mod q = [1, 0, 0, 0, 0, 0, 0]   ← 应为 1,0,0,...
      g_A                  = [0, 0, -1, 0, -1, 1, 1]
      h_A = p*g_A*f_A^{-1}  (公钥) = [-928, -523, -168, -987, 621, -511, 448]
  对象 B（接收方 Bob）：
      f_B                  = [1, 0, -3, 3, 0, -3, 3]
      h_B                  = [-239, 938, -140, 385, 228, -139, 1015]
```

**怎么看这三行**：

- `f_A = [1, -3, 0, 3, -3, 3, 0]`：第 0 位是 `1`（常数项），其余是 `3·F_A`。逐位 mod 3 → `[1,0,0,0,0,0,0]`，这就是代码里反复强调的 **`f ≡ 1 (mod p)`**。
- `f_A^{-1}` 的系数是"随机样子"的大数，这是模 2048 下求逆的正常结果（算法见 `src/core/poly_inv.cpp`：先在 GF(2) 上做扩展欧几里得，再做 4 次 Newton/Hensel 提升到 mod 2¹⁶）。
- `h_A = 3·g_A·f_A^{-1}`：公钥里**看不出** `f_A`（它被 `f_A^{-1}` 打散了），这就是 NTRU 的安全性来源。
- 注意密钥尺寸：**每个都是 1 个多项式**，不管是 n=7 还是 n=1499，都是 `n·log₂(q)/8` 字节（n=1171 时约 1.57 KB）。这是 NTRU 系 PRE 相对 LWE 系 PRE 的最大卖点。

**手工验算（第一个系数，强烈建议自己算一遍）**：循环卷积 `c[k] = Σ_i f[i]·f^{-1}[(k−i) mod n]`，取 `k=0`：

```
c[0] = 1·(−132) + (−3)·(−280) + 0·(−1014) + 3·307 + (−3)·539 + 3·679 + 0·(−98)
     = −132 + 840 + 0 + 921 − 1617 + 2037
     = 2049 ≡ 1 (mod 2048)   ✓
```

（注意下标要和 b 反着配：`f[1]` 配 `f^{-1}[6]`，`f[3]` 配 `f^{-1}[4]`…… 这正是"循环卷积 + 中心下标"最容易错的地方。）

### 【步骤 2】Alice 加密两个数据对象 —— `ntru.cpp : encrypt()`

```
  数据对象 #1（将被授权给 Bob）：
      明文 M1  (mod p, 0/1/2)  = [0, 2, 0, 0, 1, 0, 0]
      随机 s1（dr 重量三元）   = [-1, 1, 1, -1, 0, 0, 0]
      密文 C1 = h_A*s1 + M1    = [244, 556, 317, -824, 796, 313, 649]
  数据对象 #2（不授权给 Bob，用 Alice 的另一个"授权域"密钥对 A2）：
      A2 的公钥 h_A2           = [47, 788, -789, -135, 752, 18, -681]
      明文 M2                  = [1, 0, 0, 0, 0, 2, 0]
      密文 C2 = h_A2*s2 + M2   = [850, 653, 690, 80, -188, 8, -42]
```

**两个对象为什么要用两把密钥**：本方案（以及 NTRUReEncrypt）的委托粒度是**"用户对"**，不是"数据对象"。
一份 `rk_{A→B}` 能转换 Alice 用同一把 `f_A` 加密的**所有**密文。所以要做到"对象 1 给 Bob、对象 2 不给"，必须让对象 2 落在**另一个授权域**（另一把密钥对 `A2`）——这就是 `方案1` 里"独立域密钥隔离授权范围"的做法，也是步骤 8(a) 要实测的东西。

**手工验算（`C1` 的第一个系数）**：

```
C1[0] = h_A·s1 + M1 的第 0 个系数
      = Σ_i h_A[i]·s1[(0−i) mod 7] + M1[0]
      = (−928)(−1) + (−523)(0) + (−168)(0) + (−987)(0) + 621(−1) + (−511)(1) + 448(1) + 0
      = 928 − 621 − 511 + 448
      = 244   ✓（与打印的 244 一致）
```

### 【步骤 3】Alice 自己解密对象 #1 —— `ntru.cpp : decrypt_with_noise()`

```
      a1 = f_A * C1 mod q        = [12, -1, -3, -3, 7, -12, 3]
    取中心代表后 mod p  ->  [0, -1, 0, 0, 1, 0, 0]
    噪声 ||center(f_A*C1)||_inf = 12   （q/2 = 1024，余量充足）
    解密结果与 M1 一致？是 ✓
```

**为什么这一步能出明文**：把 `C1 = h_A·s1 + M1` 和 `h_A = p·g_A·f_A^{-1}` 代进去：

```
f_A·C1 = f_A·(p·g_A·f_A^{-1})·s1 + f_A·M1 = p·(g_A·s1 + F_A·M1) + M1
```

第一项是 **p 的倍数**，所以 mod p 之后消失，只剩下 `M1`。
打印出来的 `a1 = [12, −1, −3, −3, 7, −12, 3]` 就是"`p·(...) + M1`"的样子：每个系数都是 3 的倍数再加一点 —— 比如 `12 = 3·4 + 0`、`−1 = 3·(−1) + 2`、`7 = 3·2 + 1`。

**手工验算（`a1` 的第一个系数）**：

```
a1[0] = 1·244 + (−3)·649 + 0·313 + 3·796 + (−3)(−824) + 3·317 + 0·556
      = 244 − 1947 + 0 + 2388 + 2472 + 951
      = 4108 ≡ 4108 − 2·2048 = 12   ✓（与打印的 12 一致）
```

**解码**：`12 mod 3 = 0` → `0`；`−1 mod 3 = 2` → 中心化成 `−1`；`7 mod 3 = 1` → `1`……
得到 `[0,−1,0,0,1,0,0]`，而 `M1 = [0,2,0,0,1,0,0]` 的中心形式也是 `[0,−1,0,0,1,0,0]` ✓
**噪声 = 12，`q/2 = 1024`**：余量 85 倍，这就是"正确解密"的量化含义。

### 【步骤 4】Alice 生成委托凭证 —— `pre_base.cpp : rekeygen()`

```
      rk_{A->B} = f_A * f_B^{-1} mod q = [-438, -114, -422, -588, -540, 987, -932]
```

**一行代码就是全部委托逻辑**。它的代数性质是：

```
rk · f_B = f_A · f_B^{-1} · f_B = f_A
```

⚠️ **这就是本项目的动机**：谁能同时拿到 `rk` 和 `f_B`（代理 + 接收者合谋，或接收者自己就能推），谁就能直接算出委托方私钥 `f_A`。步骤 8(b) 会实测这一点。
（对照：`rk` 是"小多项式 ÷ 小多项式"的形状，还会被多密钥 NTRU 格攻击盯上，见 `docs/00_design.md` §1。）

### 【步骤 5】单个代理做基线重加密 —— `pre_base.cpp : reencrypt()`

```
      噪声 e1                  = [0, -1, 0, 1, 0, -1, 1]
      C1' = C1*rk + p*e1       = [-673, -705, -578, 904, -663, 347, -677]
    Bob 解密：噪声 = 31，结果 = [0, -1, 0, 0, 1, 0, 0]   与 M1 一致？是 ✓
```

**为什么 Bob 能解出**：

```
f_B·C1' = f_B·C1·rk + p·e1·f_B = f_B·C1·f_A·f_B^{-1} + p·(...) = f_A·C1 + p·(...)
        = [p·(...) + M1] + p·(...)
```

mod p 之后两项都消失，剩 `M1` ✓

**`p·e1` 这一项不能省**：如果没有它，Bob 可以算 `f_B·C1' = f_A·C1`，而 `C1` 是公开的密文，只要 `C1` 在 `R_q` 中可逆就能直接解出 `f_A = C1^{-1}·(f_B·C1')`。加上 `p·e1` 后这条等式不再成立（多了一个未知的大噪声项）。

**噪声对照**：Alice 自己解是 12，Bob 解转换后的密文是 31。多出来的就是重加密引入的噪声。

### 【步骤 6】门限委托：3 个代理、需要 2 个 —— `threshold.cpp : cnf_share()`

```
  子集大小 = n-t+1 = 2，子集总数 C(n,t-1) = 3
    子集 1 = {P1,P2}
    子集 2 = {P1,P3}
    子集 3 = {P2,P3}
    share_1 = [-110, 375, -93, -169, -518, 122, 310]
    share_2 = [966, -477, 188, 389, -603, -575, -597]
    share_3 = [754, -12, -517, -808, 581, -608, -645]
    Σ share  (应等于 rk) = [-438, -114, -422, -588, -540, 987, -932]
    与步骤 4 的 rk 相同？是 ✓
  代理各自持有的份额：
    P1 持有 2 份：{P1,P2} {P1,P3}
    P2 持有 2 份：{P1,P2} {P2,P3}
    P3 持有 2 份：{P1,P3} {P2,P3}
```

**手工验算（份额求和）**：

```
第 0 位：−110 + 966 + 754 = 1610 ≡ 1610 − 2048 = −438   ✓ 等于 rk[0]
第 5 位：122 + (−575) + (−608) = −1061 ≡ −1061 + 2048 = 987 ✓ 等于 rk[5]
```

**为什么不能用 Shamir 而要用这种"子集加性分享"**：
`q = 2048 = 2¹¹`，`Z_q` **不是域**（是局部环），Shamir 的重构系数 `λ_i = Π(0−j)/(i−j)` 分母含因子 2 就不可逆；取整数点 1..n 时差全是偶数 → Shamir 直接失效。改用子集加性分享后**重构系数全是 1**，不用求逆、噪声友好。完整论证见 [`最终报告.md`](../最终报告.md) §2.2。

**为什么任 2 个就够、任 1 个不够**（这是本设计最漂亮的一点）：

- 任意 2 个代理（比如 P1、P2）的并集，与每个子集都相交（因为 `|子集| = 2 > |[n]\W| = 1`）→ 它们合起来持有全部 3 份 → 能求和出 `rk`；
- 任意 1 个代理（比如 P1）只有 2 份，**恰好缺掉与它不相交的那一份**（P1 缺 `{P2,P3}`），而那一份是均匀随机的 → 它看到的两份与 `rk` 独立 → **零信息**（信息论意义下，不需要计算假设）。

### 【步骤 7】选 2 个代理做部分重加密并组合 —— `threshold.cpp : proxy_partials() / threshold_combine()`

```
  参与集合 W = {P1, P2}（满足 |W| = t = 2）
    partial_1 (由 P1 提供)  = [595, 161, -680, -201, 851, 706, 367]
    partial_2 (由 P1 提供)  = [804, 51, 512, -232, -443, 846, 431]
    partial_3 (由 P2 提供)  = [-18, -911, -413, -714, 974, 849, 564]
    C1'' = Σ partial        = [-667, -699, -581, 901, -666, 353, -686]
    Bob 解密：噪声 = 54（基线为 31，放大 1.74×），结果与 M1 一致？是 ✓
```

**每个代理在算什么**：`partial_S = C1·share_S + p·e_S`

**为什么求和就是合法密文**（纯线性代数）：

```
Σ_S partial_S = C1·(Σ_S share_S) + p·(Σ_S e_S) = C1·rk + p·e_total
```

因为 `Σ share_S = rk`（步骤 6 验证过），所以组合结果**就是**基线的 `C1'`，只是噪声从 1 份 `p·e` 变成 3 份之和。

**注意"由谁提供"这一列**：子集 `{P1,P2}` 同时被 P1、P2 持有，代码里用 `owner = min(S ∩ W)` 规则保证**每个子集只被算一次**（否则会重复相加，结果就错了）。这是实现门限组合时最容易出 bug 的地方。

**噪声代价曲线**（这正是报告要画的核心图）：

| 配置 | 子集数 | Bob 解密噪声 | 相对基线 |
|---|---|---|---|
| 基线单代理 | 1 | 31 | 1.00× |
| 门限 (n=3, t=2) | 3 | 54 | 1.74× |
| 门限 (n=5, t=2) | 5 | — | ≈2.3×（n=61 测试参数下的实测值） |
| 门限 (n=5, t=3) | 10 | — | ≈2.65× |

**读法**：噪声随子集数的增长明显**慢于线性**（典型是 `√C(n,t−1)` 量级，因为各份噪声独立、取的是 ∞-范数）。门限化换来的是"腐化阈值从 1 个代理提到 t 个代理"，代价是噪声预算被吃掉一部分 → 可支持跳数下降。**这个 trade-off 就是 C1 + C2 的结合点。**

### 【步骤 8】两个安全事实的实测 —— 对象级隔离 + rk 泄漏

```
  (a) 用 rk_{A->B} 去转换对象 #2 的密文 C2（跨授权域）：
      Bob 解密得到的噪声 = 997，结果 = [-1, 1, -1, -1, 0, 1, 0]
      与 M2 一致？否 ✓
      rk * f_B  mod q            = [1, -3, 0, 3, -3, 3, 0]
      f_A（步骤 1 里的私钥）     = [1, -3, 0, 3, -3, 3, 0]
      两者相同？是 ✓（这就是本项目要解决的问题）
```

**(a) 为什么跨域转换会失败**：`C2` 是用 `h_A2` 加密的，拿 `rk_{A→B}` 去转换后 Bob 得到的不是 `M2`。
关键是**失败的原因是密码学的，不是应用层的 `if`**：

```
f_B·(C2·rk) = f_A·C2 = f_A·(h_A2·s2 + M2)
            = 3·f_A·g_A2·f_A2^{-1}·s2 + f_A·M2
```

- mod 3 看：`f_A ≡ 1 (mod 3)`，所以理论上应该剩下 `M2`；
- **但第一项在整数意义上是巨大噪声**：实测 `‖center(f_B·C2·rk)‖_∞ = 997`，已经逼近 `q/2 = 1024`。一旦超过 `q/2`，取中心代表就会"绕回"，模 3 的结构被破坏 → 解出来是乱的。

所以"对象级授权隔离"是由**密钥域 + 噪声预算**保证的：不同授权域用不同密钥对，跨域转换必然噪声爆掉。这也解释了为什么 `方案1` 强调"只给一把全局公钥的密文加标签挡不住持有 rk 的代理"。

**(b) `rk · f_B = f_A` 实测相等**：确认了基线 NTRUReEncrypt 的致命弱点在真实数字上成立 —— 代理与接收者一合谋，零成本恢复委托方私钥（连格约化都不需要）。
门限版的意义就在于：单个代理手里只有 `rk` 的**份额**，且份额是均匀随机的（步骤 6），所以这条"合谋链"必须先凑齐 `t` 个代理才成立。

---

## 3. 从这次预演里能直接得出的 5 个结论

1. **整条链条只有两个数学动作**：`f·C` 消掉 NTRU 噪声（中心代表 + mod p 解密），以及"乘 `rk` 把委托方的密钥换成接收方的密钥"（`rk = f_A·f_B^{-1}`）。
2. **`f ≡ 1 (mod p)` 不是优化而是正确性前提**：`f·M` 项必须 mod p 后仍等于 `M`。
3. **`p·e` 掩码是必须的**：否则接收者能从转换后密文反推 `f_A`。
4. **门限化是"用噪声预算换安全阈值"**：`Σ share = rk` 保证了正确性，代价是噪声从 1 份变成 `C(n,t−1)` 份之和（实测 1.7~2.7×）。
5. **授权隔离必须靠密钥域**：跨域转换的失败源于噪声越过 `q/2`（实测 997 vs 1024），而不是任何软件判断。

## 5. 附：开发骨架时踩到的坑（同源现象，值得记在报告里）

- **"常数多项式" vs "逐系数操作"**：`poly_inv.cpp` 里 Newton 提升写的是 `h = 2 − f·g`，其中 "2" 只有第 0 个系数是 2。第一版误写成"每个系数都减 2"，结果是**求逆静默失败、所有密钥都生成不出来**（自检直接报 `keygen 成功（f 可逆）= FAIL`）。这类"没有异常、只有错误结果"的坑是格密码实现的常态。
- **循环卷积的下标配对**：`c[k] = Σ_i a[i]·b[(k−i) mod n]`，下标要反着配（`a[1]` 配 `b[n−1]`）。手工验算时最容易在这里算错，而算错了会以为代码有 bug。
- **int64/int32 累加溢出**：三元系数可以安全用 int32 累加，但**满量程 mod 2048 的乘积**（只有 ReEnc 的 `C·rk` 是这种）会到 `n(q−1)² ≈ 4.9e9 > 2³¹`，必须 int64 或 int32+分块归约。详见 `README.md` §4.2。
