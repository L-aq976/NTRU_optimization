# 格在哪里？—— 这个项目里的"格"到底体现在哪

> 疑问：**主要数学计算都在环 `Z_q[x]/(x^n−1)` 里做，这和格密码有什么关系？代码体现在哪里？**
> 配套代码：`pyref/attack_lattice.py`（本文件说的"格"就写在这里，可直接跑）
> 版本：2026-10-13

---

## 0. 一句话回答

> **算法算的是环，安全性靠的是格。**
> 你在代码里看不到格基、格向量、约化，是因为**格是攻击者眼里的对象，不是我们的计算载体**。
> 这和 Kyber 一模一样：Kyber 是标准格密码（ML-KEM，FIPS 203），但它的实现里只有 NTT 和多项式运算，一个格基都找不到。

判断一个方案"是不是格密码"，标准**不是**"代码里有没有格矩阵"，而是"**它的安全假设是不是格上的困难问题**"。

---

## 1. 格是怎么"藏"进环运算里的：一条等价关系

关键只有一条式子（`src/core/ntru.cpp : keygen()` 里的那一行）：

```
h = p · g · f^{-1}  (mod q)
```

把它两边乘 `f`：

```
f · h ≡ p · g   (mod q)
```

这个同余式说的就是：**向量 `(f, p·g) ∈ Z^{2n}` 属于下面这个格**

```
Λ_h = { (u, v) ∈ Z^{2n} :  v ≡ u * h  (mod q) }
```

而 `f`、`g` 都是**小系数多项式**（系数只有 0/±1、±2、±3），所以 `(f, p·g)` 是这个格里**特别短**的向量。

于是：

> **"从公钥 h 求私钥 f" ≡ "在 2n 维格 Λ_h 里找短向量"（SVP）**
> LLL / BKZ 就是干这个的工具，`det(Λ_h) = q^n`。

这就是格密码里的"格"。你的环运算本身没错——**环是计算，格是难度**。

## 2. 代码里的三处（一张表）

| 位置 | 文件 / 函数 | 格体现在哪里 |
|---|---|---|
| **参数** | `src/core/params.cpp` | `(n, q, df, dg)` 的**唯一**正当性来自"格约化要花多少代价"的估计。n 从 439 → 1171 → 1499，本质是在跟 BKZ 赛跑；q=2048 和 df/dg 的取值也由噪声/短向量分析决定。**这就是"格"以数字形式进入了代码。** |
| **公钥生成** | `src/core/ntru.cpp : keygen()`，`h = p·g·f^{-1} mod q` | 这一行**造出了格实例** `Λ_h`。之前没有任何"格"，这一行之后，攻击者的目标就变成了"在 Λ_h 里找短向量"。 |
| **攻击** | `pyref/attack_lattice.py`（本文件的主角） | **唯一真的把格矩阵写出来的地方**：`build_ntru_lattice()` 显式构造 2n×2n 的整数基矩阵，LLL 约化，再在短向量里找私钥。 |

> 除了这三处，其余代码（Enc / Dec / ReKeyGen / ReEnc / 门限分享 / 组合）**确实一个格都没有**，全是环运算。这是正常的。

## 3. 攻击代码：格是怎么写出来的

### 3.1 构造 Λ_h 的基（2n 行 × 2n 列，行向量）

```
        ⎡  I_n       H   ⎤        H[i][j] = h[(j − i) mod n]   （循环卷积矩阵）
        ⎣  0      q·I_n ⎦        ⇒ 格向量形如 (u, u*h + q·w)
```

- 上半 `[I_n | H]`：取 `u = e_i`，第二块就得到 `h` 的循环移位 → 保证 `v ≡ u*h (mod q)`；
- 下半 `[0 | q·I_n]`：允许在第二块上加减任意 `q` 的倍数 → 这正是同余的自由度。

代码：`pyref/attack_lattice.py : build_ntru_lattice()`

### 3.2 目标向量 vs 格的随机短向量

| 量 | 公式 | TINY7 (n=7) | EES439 (n=439) |
|---|---|---|---|
| 格维数 | `2n` | 14 | 878 |
| `det(Λ_h)` | `q^n` | `2^77` | `2^4829` |
| 私钥向量范数 `‖(f, p·g)‖` | `√(2·df + p²·2·dg)` 量级 | 8.19 | **51.3** |
| 高斯启发式最短向量 | `√(dim/2πe)·det^(1/dim)` | 40.97 | **324.5** |
| **全 1 向量范数** | `√n` | **2.65** | **20.95** ← 比私钥还短，见 §4 |

### 3.3 实跑结果（本机 Windows + SymPy 精确 LLL）

```
$ python pyref/attack_lattice.py --params TINY7 --seed 1
  格 Λ_h：维数 2n = 14，det = q^n = 2^77.0
  真私钥 f = [-2, 3, 3, 0, 0, -3, 0]
  正在 LLL 约化（维数 14）... 完成：耗时 0.29 s
  ✓ 找到 1 把能正确解密的密钥：
      u = [-2, 3, 3, 0, 0, -3, 0]   与真私钥 f 相同？是 ✓（精确恢复）
```

**私钥被完整恢复出来了** —— 这就是"格"在起作用：我们没有用任何环上的技巧，纯粹靠"在格 Λ_h 里找短向量"。

### 3.4 真实参数为什么打不动（这张表就是"安全参数"的含义）

```
$ python pyref/attack_lattice.py --params EES439 --seed 3
  格 Λ_h：维数 2n = 878，det = q^n = 2^4829.0
  目标短向量 (f, p*g) 范数 ≈ 51.30
  格的高斯启发式最短向量长度 ≈ 324.47
  ⇒ 目标只比随机格的最短向量短 6.3 倍
  LLL 最坏逼近因子 ≈ 2^(dim/4) = 1.19e+66     ← 差得远
```

读法：**LLL 的能力（2^(dim/4)）与"目标比 GH 短多少倍"之间的差距，就是安全裕度**。
维数一大，就必须上 BKZ 并不断提高块大小 β —— **BKZ-β 的时间复杂度就是论文里说的"安全位数"**。
（要实跑大维数：WSL 里 `pip install fpylll`，然后 `--backend fpylll --max-dim 2000`。）

## 4. 只有动手才会发现的两个细节（写进报告很加分）

### 4.1 格里有一个**比私钥还短**的向量：全 1 向量

因为 `g` 的采样是 **dg 个 +1、dg 个 −1**，所以它的系数和恒为 0：

```
(1 + x + ... + x^{n−1}) · g = (Σ g_i)·(1 + x + ... + x^{n−1}) = 0
⇒ (all-ones) · h = p · (all-ones)·g·f^{-1} = 0
⇒ 向量 (1, 1, ..., 1, 0, ..., 0) ∈ Λ_h，范数只有 √n
```

对 n=439 是 **20.95**，而私钥向量是 **51.3** —— **私钥根本不是格的最短向量！**

所以"在 Λ_h 里找最短向量"**不等于**"找私钥"。这个坑不自己跑一遍是发现不了的（我们第一版脚本就被它骗了：LLL 一上来就返回全 1 向量，看起来"范数最小、攻击成功"，其实解密出来全是 0）。

### 4.2 私钥还必须满足 `u ≡ 1 (mod p)`

解密要成立，需要 `u·C = u·h·s + u·M` 在 mod p 之后**恰好等于 M**，这要求

```
u ≡ 1  (mod p)        （即 u 的常数项 ≡ 1、其余系数 ≡ 0 mod 3）
```

全 1 向量显然不满足（它 mod 3 是 `1+x+...+x^{n−1}`），所以它是"退化钥匙"。
加上这个过滤之后：

| 搜索策略 | TINY7 结果 |
|---|---|
| 只逐行检查约化基 | ✗ 找到 6 个短向量，全部"残留类不对"，解密失败 |
| 最短 6 行、系数 {−1,0,1}（729 种）| ✗ 不够 |
| **最短 8 行、系数 {−1,0,1}（6561 种，0.01 s）** | **✓ 唯一命中，精确恢复真私钥** |

→ 结论：**LLL 只负责"约化"，真正恢复私钥靠"约化 + 按结构条件枚举短向量"**（这正是文献里 NTRU 攻击的标准收尾）。

## 6. 三个常见误区（书面回答用）

| ❌ 错误说法 | ✔ 正确说法 |
|---|---|
| "我们用了格上的运算" | 我们用**环**上的运算（`Z_q[x]/(x^n−1)` 的加、循环卷积、求逆）；**安全性归约到格上的困难问题** |
| "代码里没有格基/LLL，所以这不是格密码" | Kyber 的实现里也没有格基；判断标准是**安全假设**，不是代码里有没有格矩阵 |
| "NTRU 有显式噪声 e，所以它更像 LWE" | NTRU 的"误差"藏在小多项式 `f, g` 里（`h = p·g·f^{-1}`），**没有独立噪声**；它归约到 NTRU 格（多密钥 NTRU 格）上的 SVP，而不是 LWE。它是格密码里独立于 LWE 的一支 |

## 7. 复现命令

```bash
# 1) 小参数：真的能恢复私钥（维数 14，秒级）
python pyref/attack_lattice.py --params TINY7  --seed 1

# 2) 真实参数：只给理论分析（维数 878，LLL 差 2^219 倍）
python pyref/attack_lattice.py --params EES439 --seed 3

# 3) WSL 里装了 fpylll 之后（推荐，快且支持 BKZ）
pip install fpylll
python3 pyref/attack_lattice.py --params TINY61 --backend fpylll --max-dim 2000
python3 pyref/attack_lattice.py --params EES439 --backend fpylll --max-dim 2000
```

> 注：Windows 上 `pip install fpylll` 会尝试从源码编译（需要 GMP/MPFR），装不上；脚本会自动退回 **SymPy 自带的精确 LLL**（Anaconda 自带 sympy），能处理 ≤ 32 维。
