# web/ —— 门限代理重加密演示前端

按 `lively-dancing-stream.md` 的思路实现的前端。**导航只放两页，没实现的里程碑不出现**：

- **`#/live` 现场演示（默认）**：9 个节点、任意 6 个。点「开始演示」看密钥生成 → 加密 →
  委托凭证 `rk` → 拆成 126 份份额 → 发给 9 个节点 → 选 6 个 → 126 份 partial → 组合 →
  Bob 解密，一步步动起来；**所有系数都是浏览器里现算的**（`js/ntru.js`）。
  支持**整步暂停 / 单步**：暂停只落在步骤边界，当前这一步一定做完（"分发 126 份份额"算一步）。
- **`#/c1` C1 数据**：录制数据看板（成功率 / 噪声放大 / 三阶段耗时 / 21 行表 / 口径）。

没有构建步骤、没有 CDN、没有第三方库、不需要 Node/Python 才能看。

直接双击 `web/index.html`（`file://` 可用，脚本是普通 `<script>`，不是 ES module）。
后续里程碑由 `bin/ntru_demo.exe` 把 `web/` 当静态根目录提供，同一份文件原样复用。

## 演示页的部署形态：4 / 4 / 1

页面按"方案 B"画：A 的 4 个代理挂在 **A 网关**、B 的 4 个挂在 **B 网关**（各一台 GPU 机器），
中立平台只占 **1 个**代理、同时当密文舞台（组合者）。默认参与集合 = A×4 + 平台×1 + B×1，
所以任何一次转换都要两方以上到场。

为什么一台机器最多代表 t−1 = 5 个代理：CNF 里每个代理持 56 份，**4 个代理合起来覆盖
121/126 份，5 个覆盖 125/126 份**（还差 1 份均匀随机 ⇒ 零信息），**6 个就 Σshare = rk**。
把 9 个代理塞进一台机器，门限直接作废——演示页里的「算力归属」那段就是写这个。

GPU 只在**批量**时划算（`bench/results/gpu_kernel_sweep_i32twoseg.csv`，n=1171）：

| batch | kernel-only µs/次 | 端到端 µs/次 | 端到端加速 |
|---|---|---|---|
| 1 | 78.5 | 211.1 | 0.72×（比 CPU 慢） |
| 16 | 4.94 | 16.1 | 9.45× |
| 8192 | 2.03 | 14.6 | 10.5×（kernel 75×） |

一次 9-of-6 只有 126 次卷积，上 GPU 省不出多少；收益来自"同一网关对一批密文"，
即 batch = 代理数 × 56 × 密文条数。**演示页里的算术仍由浏览器完成**，GPU 说的是部署形态。

## 演示页：q 为什么要调

9 个节点要 6 个才够（t=6）⇒ 子集大小 `9−6+1=4`、份额数 `m=C(9,5)=126`，每节点持 56 份
（约 33.8 KB）。每份 partial 都要加一次 `p·e` 掩码，于是解密时
`‖center(f_B·ct)‖∞` 随份数上涨；`q/2` 就是预算，越过就绕回、`mod 3` 结构被破坏。

实测（n=439、seed=20261012、本页引擎）：

| 场景 | 噪声 ‖·‖∞ | q/2 | 结果 |
|---|---|---|---|
| 单代理（1 份） | ~392 | 1024（q=2048） | ✓ 成功 |
| 9-of-6（126 份） | 顶到 1021 | 1024（q=2048） | ✗ 绕回 |
| 9-of-6（126 份） | 顶到 2044 | 2048（q=4096） | ✗ 绕回 |
| **9-of-6（126 份）** | **5057** | **8192（q=16384）** | **✓ 成功（61.7%）** |
| 9-of-6 但只用 5 个节点 | —（ct 与 rk 无关） | — | ✗ 结构性失败（缺 1 份） |

所以页面上留了 q 的档位（2¹¹…2¹⁸）和一键「把 q 提到 16384 再跑一次」。**增大 q 只是把预算
撑开，不是免费的**：同样的 n 下 q 变大，格攻击更容易，真实部署要连 n 一起加 —— 这条写在页面
的读法里，别当成"调大 q 就安全了"。

## 数据纪律（重要）

页面上的三类数字，来源互不混淆，界面上都有徽章标注：

| 数字 | 来源 | 标注 |
|---|---|---|
| 成功率、噪声放大、三阶段耗时 | `data.js` ← `bench/results/c1_*.csv`（报告数字的唯一来源） | ✓ 录制数据 + 文件名 / mtime / 试验数 |
| 子集数 `m=C(n,t−1)`、每代理持有份数、缺失子集、存储估算 | `threshold.js` 由 `(n,t,W)` 精确算出（纯结构，无随机数） | ⓘ 结构实时推导 |
| 抽样条（✓/✗ 小方块） | 由录制成功率四舍五入出通过数、固定种子打散位置 | ◐ 抽样演示 |

**改数据的唯一方式**：重跑 `bin/ntru_cli.exe c1 <参数集> <trials> <zero_trials>` 后，
把新的 `bench/results/c1_*.csv` 手工同步进 `js/data.js`（21 行，量很小）。
不要在图里写死任何数字。

```bash

# 2) 页面（真浏览器）

#   web/test/page.test.html   C1 数据页     → 78 条（**要用 HTTP 起 mock 后端**，见下）

# 3) 也可以起 mock 后端再测（顺带验静态服务 + /api/health 在线徽章）
```

## 已知限制

- `file://` 下浏览器不允许 fetch 本地文件，所以数据是内联在 `data.js` 里的，不做运行时读 CSV。
- 表格与图表里的耗时是**单核 CPU 功能基线**，与机器/编译选项强相关；成功率与噪声放大是代数性质。
- `js/ntru.js` 是**独立的浏览器实现**（公式逐条照抄 `src/core`，q 允许不是 2^11）。仓库的 C++
  引擎仍是唯一权威实现；两者在 q=2048 下给同一量级的噪声（单代理 ~200–400），但没有做逐位对拍。
- 演示页每次跑要现算 126 份 `C₁·share`（n=439），4× 速度下约 0.2 s/轮在算，其余时间是在演动画。
- 图表用 `viewBox` 自适应，窄屏下阶段标签会隐藏函数名（`cnf_share()` 等）。
